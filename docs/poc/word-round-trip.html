Why a rule is writable here

Parsing an arbitrary Word file into a strict schema is not reliably possible. But we hand out the document, so it can be built from Word's own structures rather than from text conventions. Each issue is wrapped in a content control whose w:tag carries its stable iss-… id, locked so the frame cannot be deleted while its contents stay editable. Reading back is then a lookup, not an inference.

The tag carries identity only, never placement. Where an item sits comes from the container it is in and from document order — which is what makes dragging a box mean something.

What each document state means

What the document showsRead as
Text changed inside a boxAn edit to that issue. Tracked insertions count as accepted; tracked deletions are dropped.
Something typed into an add here slotA new issue. An untouched slot is never a phantom addition.
Title, view and all three cells emptyRetire the issue. Confident.
Only the three cells emptyDrop the signposts, keep the issue.
The frame is gone entirelyRebuilt from the style anchor and matched by title. If that fails: retire, flagged as possibly accidental.
Title empty, content still thereNeither — a question in the review.
One or two cells of three filledNeither — a question. validate() would otherwise refuse the whole import.
An id on disk that the document never hadAdded by someone else since export. Left exactly as it is.

How it is wired into the editor

One new DOCX module beside the existing YAML one, exposing write(eco) and read(buffer). Everything after Review changes is the machinery that already exists.

1Word copyA per-economy button in the toolbar. It builds the bytes in memory and downloads them, so it needs no write permission and no editors: entry — a reviewer who never edits can still get one.
2Edit in WordTrack Changes and comments are fine. The file name carries the version: united-states-v2.docx.
3ImportThe same button and dialog, with .docx added to the file input. It branches on the extension and reads the file as an array buffer.
4ReviewThe Word path clones what is on disk now and applies per-issue deltas, because the document is a projection — it omits the implications matrix and can go stale. That makes a stale Word file safer than a stale Ada file, which replaces everything.
5ApplyThe normal save path: version + 1, the on-disk conflict check, one log entry with source: word-import, lock released.

What is still unproven

There is no copy of Microsoft Word in the environment this was built in. The file is well-formed OOXML and an independent reader opens it, but Word is the authority on three things: that it opens without a repair prompt, that it preserves the w:tag values on save, and that sdtLocked really stops a frame being deleted. That is one half-hour test, and it is step zero of any build.
